GHOSTGRAM — USERNAME-ONLY SIGNUP UPDATE

WHAT CHANGED
- Sign up with a username + password; recovery email is optional.
- Log in with username + password.
- Password confirmation is checked.
- New username accounts use a private Firebase Auth alias (username@ghostgram.invalid). This is an internal login identifier, not a real mailbox.
- Google sign-in remains available.

IMPORTANT LIMITS
- Email-free accounts cannot receive password-reset emails. If you add a recovery email, it is stored in the private users/{uid} profile as contact information, but automatic password recovery is not configured in this starter.
- Existing accounts created with a real email before this update may need to keep using the old email login; this username-only flow is for newly created accounts.
- Username registry entries are publicly readable so the app can resolve a username at login. They contain only the Firebase UID and the synthetic login alias, never the recovery email. Do not put private information in a username.
- This is still a starter project, not a production social network. Public launch needs stronger abuse protection, recovery design, moderation/report/block tools, privacy policy, age safeguards, and secure cloud media rules.

STEP 1 — UPDATE FIRESTORE RULES
Firebase Console > Build > Firestore Database > Rules.
Replace the current rules with the following and tap Publish:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid} {
      allow read, create, update: if request.auth != null && request.auth.uid == uid;
      allow delete: if false;
    }
    match /usernames/{username} {
      allow read: if true;
      allow create: if request.auth != null
                    && request.resource.data.uid == request.auth.uid
                    && request.resource.data.keys().hasOnly(['uid', 'loginEmail']);
      allow update, delete: if false;
    }
    match /{document=**} {
      allow read, write: if false;
    }
  }
}

STEP 2 — REPLACE WEBSITE FILES
1. Open your GitHub repository: rehan456hus-netizen/GhostGram.
2. Upload and replace the files from this ZIP in the repository root. Keep the existing firebase-config.js with your Firebase Web App config.
3. Commit the changes. GitHub Pages will redeploy the site.
4. Open https://rehan456hus-netizen.github.io/GhostGram/ and reload.

STEP 3 — TEST
1. Tap Sign up.
2. Enter a new username (3–20 letters, numbers or underscore).
3. Recovery email can be left blank.
4. Enter a password of at least 6 characters and confirm it.
5. Create account, log out, then log in with the username and password.

Do not share passwords, OTPs, service-account JSON, or private keys. Firebase client config is designed to be present in a web app, but database rules must remain restrictive.

CURRENT APP LIMITATIONS
- Feed, stories, reels, likes, comments, search and posts remain demo/local UI; they are not cloud-synced between users.
- Password reset is unavailable for accounts without a real email-based recovery flow.
- Existing older email accounts are not automatically migrated.
- Google popup may be blocked by some mobile browsers.
