GHOSTGRAM FIREBASE AUTH SETUP (READ FIRST)

This project includes Firebase Authentication code for:
- Sign up with email + username + password
- Log in with username OR email + password
- Forgot password via email reset link
- Continue with Google
- Sign out

IMPORTANT: Firebase is NOT connected yet. You must create/configure your own Firebase project.
Do not send anyone your password, Google password, service-account JSON, private keys or OTPs.
The Firebase Web App config is intended for client apps; still restrict its API usage and set
Firestore security rules before launch.

A. CREATE FIREBASE PROJECT (Chrome on Android)
1. Open https://console.firebase.google.com/ and sign in with your Google account.
2. Create a project named GhostGram.
3. In Project Overview, tap Add app > Web (</>), register app as GhostGram Web.
4. Copy the Firebase config object shown by Firebase.
5. Open firebase-config.js in this ZIP and replace each PASTE_... value with your real values.
   Do not paste a service account key here.

B. ENABLE SIGN-IN PROVIDERS
1. Firebase Console > Build > Authentication > Get started.
2. Sign-in method > Email/Password > Enable.
3. Sign-in method > Google > Enable; choose a support email and save.
4. Authentication > Settings > Authorized domains: add your deployed website domain.
   For local testing, use Firebase's supported localhost flow only from a local development server.

C. CREATE FIRESTORE
1. Build > Firestore Database > Create database.
2. Start in production mode.
3. Create database in a region near your expected users, considering that region cannot easily be changed.

D. FIRESTORE RULES
Publish these starter rules in Firestore > Rules. They protect each user's profile document.
The username registry is readable so username login can look up the matching email; clients may
create a username mapping only when signed in as the matching UID. Do not allow edits/deletes
of mappings from clients. For a production public username directory, add abuse prevention.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid} {
      allow read, create, update: if request.auth != null && request.auth.uid == uid;
      allow delete: if false;
    }
    match /usernames/{username} {
      allow read: if true;
      allow create: if request.auth != null
                    && request.resource.data.uid == request.auth.uid;
      allow update, delete: if false;
    }
  }
}

E. HOST WEBSITE
1. Upload the extracted project folder to an HTTPS static hosting service.
2. Add the deployed HTTPS domain to Firebase Authentication > Settings > Authorized domains.
3. Open the HTTPS website in Chrome and test signup, logout, login, forgot password and Google.
4. Chrome menu > Install app / Add to Home screen if offered.

CURRENT LIMITATIONS / NEXT DEVELOPMENT
- Username login uses a Firestore username -> email mapping. Username reservation needs a trusted
  server/transaction to fully prevent races and abuse before public launch.
- Google sign-in may need redirect-based sign-in on some mobile browsers; popup flow is included
  as a starter and may be blocked by browser settings.
- The social feed, likes, comments, stories, reels and messages are still demo/local UI.
  They are NOT yet cloud synced between users.
- Image preview in this demo uses browser local storage/data and is not production media hosting.
- Do not launch publicly until Firestore rules, abuse controls, privacy policy, age-appropriate
  safety/moderation, reporting/blocking, and secure media upload rules are implemented.
- APK is not generated by this ZIP. Once the HTTPS PWA is hosted and tested, package it as an
  Android app and sign it. This requires Android build tooling (often easier on a computer or
  cloud build service); the PWA can be installed directly from Chrome meanwhile.
